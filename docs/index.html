Guided Onboarding

1. First Context Check

The fastest way to experience Tokonomics without sending prompts to any external AI provider or altering your workspace.

Step 1

Open any text or source file in your editor

Either highlight a few functions you want to analyze, or leave the cursor anywhere in the file.

Step 2

Trigger the command

Open the Command Palette (Ctrl+Shift+P / Cmd+Shift+P) and select:

Tokonomics: Run First Context Check
Step 3

Review the interactive dashboard estimation

Tokonomics opens the Dashboard with a step-by-step 5-stage tracker displaying:

  • Active Scope: Shows whether your selection or entire editor buffer is targeted.
  • Character & Byte Count: Exact UTF-8 input weight.
  • Estimated Raw Tokens: Fast BPE token count using the calibrated tokenizer.
  • Zero-Send Guarantee: Explains that no request was transmitted to upstream LLMs.
💡
Safety Invariant: First Context Check stores a single boolean completion flag in local storage upon finish/dismiss. It reads zero sensitive content and performs zero background network requests.

Status Bar Telemetry

3. Live Context Meter

Monitor your active text selection or editor buffer size in real time directly from the VS Code status bar.

Step 1

Turn on Context Meter (Opt-in)

Context Meter is completely opt-in to avoid unnecessary background overhead. To start:

Tokonomics: Start Context Meter
Step 2

View live status bar pill

A new item appears in the bottom right status bar:

⚡ Tokonomics: 842 tokens (Selection)

Select different code blocks or switch files; the counter updates automatically.

Step 3

Turn off anytime

Click the status bar item directly, or run Tokonomics: Stop Context Meter. Disposing drops all listeners immediately.

🛡️
Safety Boundary: Strict 300 KiB input limit. Buffers larger than 300 KiB automatically show "Input too large" to prevent UI thread lag.
Anti-Drift Technology

4. Chat Handoff (/handoff)

Reset your context window from 80k+ tokens down to 2.5k tokens with zero requirement amnesia.

Step 1

Reach Turn 15–25 in a long conversation

As chats grow past 20 turns, context drift degrades model intelligence and wastes thousands of tokens per prompt re-feed.

Step 2

Trigger Chat Handoff

In Tokonomics Chat, type /handoff or run from the Command Palette:

Tokonomics: Create Chat Handoff
Step 3

Review the synthesized checkpoint

An unsaved Markdown document opens instantly containing a distilled blueprint:

# Session State Handover [tokonomics-handoff/v1]
## 1. Active Objectives & Completed Tasks
- [x] Implemented Tree-sitter WASM parser
- [/] In Progress: Fix edge case in decorator preservation
## 2. Key Architectural Decisions
- Preserved control-flow guard blocks across all AST reductions
## 3. Touched Files & Touchpoints
- `src/compiler/ast.ts` (lines 45-80)
## 4. Next Immediate Action
- Run `npm test tests/ast.test.ts`

Start a brand-new chat session, paste this 2k token summary, and enjoy clean 97% context savings with full task continuity.

Diagnostic Surgery

5. Session Health & Zombie Log Audit

Analyze Claude Code session logs to detect repetitive tool outputs, dead terminal dumps, and context bloat.

Step 1

Run Session Log Health

Tokonomics: Analyze Session Log Health
Step 2

Select a supported .json or .jsonl session log

Choose an external agent log from your project or Claude Code directory.

Step 3

Inspect the diagnostic report on the Dashboard

Tokonomics inspects the log in read-only mode and reports:

  • Context Growth Trajectory: Starting tokens vs peak tokens and growth rate.
  • Large Tool Results: Terminal outputs or file reads exceeding 10,000 characters.
  • Repeated Tool Results: Identical commands re-feeding multiple times.
  • Compaction Markers: Boundary points where summaries were created.
Agent Engineering

6. Tool-Schema Overhead Audit

Audit your MCP server tools or OpenAI function schemas to catch parameter bloat, verbose prompts, and missing enums.

Step 1

Select tool JSON or choose a file

Highlight JSON in your editor containing OpenAI functions, MCP inputSchema, or Claude input_schema definitions.

Step 2

Run Tool Schema Audit

Tokonomics: Audit Tool-Schema Overhead
Step 3

Review the linting report

An unsaved Markdown report flags architectural defects:

  • Dominant Schema: Identifies if one massive tool consumes >40% of the entire tool definition budget.
  • Verbose Descriptions: Flags parameter descriptions >512 characters.
  • Flat Parameter Explosion: Flags tools with >6 flat arguments that confuse models.
  • Deep Nesting: Flags schemas nested deeper than 8 levels.

SECURITY CONTRACT

Privacy & Local-First Safety Invariants

Tokonomics is engineered from the ground up for strict confidentiality.

💻

Local Processing Only

Context compilation, AST pruning, and token counting run entirely on your local machine. No external servers or proxies sit between you and your AI model.

🚫

Zero Telemetry Sinks

We do not collect prompt text, source code, filenames, or usage analytics. There are no tracking scripts, third-party analytics, or background pricing downloads.

🛡️

Restricted Mode Fail-Closed

In VS Code Restricted Mode, all workspace scanning, file indexing, and automatic context attachment are disabled immediately.

🔑

Secret & Credential Redaction

Immediately prior to dispatch, all context undergoes credential scanning. Passwords, API tokens, and private keys are redacted.
