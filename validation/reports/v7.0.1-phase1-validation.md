## Implemented contract

The extension exposes exactly four public settings:

| Setting | Values | Default |
|---|---|---|
| `tokenOptimizer.optimizationMode` | `off`, `balanced`, `maximum` | `balanced` |
| `tokenOptimizer.workspaceContext` | `none`, `selection`, `automatic` | `selection` |
| `tokenOptimizer.includeUnsavedChanges` | Boolean | `false` |
| `tokenOptimizer.responseReuse` | Boolean | `true` |

A single typed preference registry now resolves manifest values, internal profiles, migration,
feature flags, diagnostics, provider/chat behavior, and dashboard state. The versioned v6
compatibility resolver recognizes every retired key, maps known values conservatively, gives
explicit v7 values precedence, and records migration once. Malformed values resolve safely.
The default migration does not enable automatic workspace access, project memory, or a local
model.

Component availability is separated from observed execution. Dashboard and diagnostic status
now use request receipts. Preview intelligence remains disabled by all public profiles. Shadow
work cannot report contribution, and disabled compiler stages are not called.

## Audit conclusions

- No declared public setting is unused.
- No additional user-facing runtime setting is read outside the four-setting contract.
- All 38 retired v6 keys are covered by bounded compatibility recognition.
- Explicit v7 settings override legacy values, including workspace-folder scope.
- Off mode prevents optimization, retrieval, signal, and cache work in the tested request path.
- Restricted workspaces cannot present restricted capabilities as available.
- An empty or discarded result is reported as fallback, not contribution.
- The pre-existing untracked `.github/workflows/` directory is unrelated and was not modified or staged.

## Limitations and residual validation

- The package remains version `6.0.0` by design. The plan changes it to `7.0.1` only in Phase 11.
- Installed-VSIX matrix certification is reserved for Phase 11; this phase validates the source
  runtime, tests, and production bundle.
- The plan's human-comprehension gate requires repository-owner review of the four setting labels
  in VS Code. Automated tests can prove simplicity and parity, but cannot substitute for that review.
- Preview components remain unavailable until their owning phases provide output-effect and
  installed-artifact evidence.
