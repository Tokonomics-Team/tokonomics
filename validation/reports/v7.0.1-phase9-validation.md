# Tokonomics v7.0.1 — Phase 9 validation

## Result

PASS. Context selection now has one typed utility function, whole-request budgeting includes protocol parts and provider request options, history is bounded before processing, and extension-authored banners/routing notices are removed before prior responses become model input.

## Implemented controls

- Typed candidate utility combines mandatory status, relevance, freshness, uniqueness, dependency closure, confidence, sensitivity risk, and token cost.
- Mandatory candidates receive monotonic priority; sensitivity and token costs reduce optional utility.
- Tools, tool mode, model options, structured parts, data, output reserve, protocol overhead, tokenizer safety, and estimator error are included in the global budget.
- Cyclic/deep/large option objects are conservatively and safely bounded while counted.
- Budget failures are typed and fail closed.
- Token measurement is explicitly labeled heuristic for the current estimator.
- Model history is capped by the active profile before image/dedup processing.
- Tokonomics banners, routing suggestions, policy notices, and cache notices remain user-visible but are stripped from model-bound assistant history.
- Cache planner/alignment claims are disabled until canonical/provider cache-control intent is preserved end to end.

## Security and privacy review

Option measurement does not log or persist values. Sanitized history is the only history passed to compilation. Restored content continues through the Phase 2 final egress security boundary.

## Rollback

Balanced/conservative pass-through selection remains available. If utility selection or exact accounting becomes uncertain, optional evidence can be omitted while mandatory content and final safety checks remain enforced.
