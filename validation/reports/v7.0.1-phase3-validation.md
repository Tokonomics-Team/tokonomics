## Implemented controls

- One request lifecycle scope now owns the request ID, deadline, composite cancellation,
  child operations, and exactly-once terminal outcome until compiler commit or failure.
- Foreground scheduling is bounded by concurrency, items, and estimated bytes, reserves capacity
  for foreground work, displaces only lower-priority queued work, and settles deadlines through
  disposable race timers.
- Worker creation is lazy, begins at the configured minimum, grows only with demand, shrinks after
  idle time, applies input/queue/task bounds, uses event-driven cancellation, and terminates on disposal.
- LSP timeout and cancellation paths no longer create polling intervals; timers and subscriptions
  are cleared in `finally` or completion handlers.
- The authoritative ledger is bounded by entries, request count, and serialized bytes. Eviction removes
  complete request histories, and persistence uses bounded debounced checkpoints rather than rewriting
  an unbounded history for every lifecycle transition.
- Local history is now a read projection of the request ledger instead of an independently persisted
  mutable array.
- Extension deactivation owns disposal of request lifecycles, schedulers, workers, index work, ledger
  persistence, listeners, and warming timers.

## Limitations and residual validation

- JavaScript cannot forcibly stop arbitrary synchronous in-process code once it is executing. Production
  CPU-heavy operations use disposable workers; the bounded in-process fallback checks cancellation before
  work, enforces input limits, and ignores late results through the same deadline contract.
- Exact retained-memory and activation/deactivation tolerances must be rerun against the packaged VSIX in
  Phase 11 because source-process measurements are not installed-artifact certification.
- The package remains version `6.0.0` until Phase 11 as required by the plan.

Rollback disables optional workers/background work while retaining bounded foreground scheduling and the
ledger caps. The unrelated untracked `.github/workflows/` directory was not modified or staged. Execution
continues directly to Phase 4 under the owner's standing approval.
