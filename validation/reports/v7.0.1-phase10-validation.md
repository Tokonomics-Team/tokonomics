# v7.0.1 Phase 10 validation

Status: automated gate passed; installed-host privacy review remains part of Phase 11.

## Implemented

- Project memory is off by default and requires trusted-workspace, explicit guided consent.
- Persistence uses VS Code Secret Storage key material and versioned AES-256-GCM records.
- Records now carry source, reason, scope, confidence, timestamps, expiry, revision, hash, sensitivity, and revocation state.
- A single management command supports add, inspect, item deletion, metadata export, disable, project deletion, and rebuild.
- High-sensitivity, expired, revoked, corrupt, injected, and hash-mismatched records cannot become candidates.
- Admitted memory passes through the normal retrieval, provenance, selection, budget, preservation, and egress gates.
- The local-model artifact manager requires explicit approval, non-empty artifacts, trusted Ed25519 signatures, SHA-256, compatible versions, approved licenses, storage and memory caps, cancellation, contained paths, and explicit deletion.
- Production contains no bundled mock/zero-byte model and performs no automatic model download.

## Promotion decision

- Project memory: promoted to opt-in conditional contribution after its candidate-path and safety tests passed.
- Local SLM: intentionally remains shadow-only and default-off. No real-model holdout ablation or supported runtime artifact exists, so reporting deterministic fixtures as model inference would be false. The signed local artifact lifecycle is ready for a future separately certified model.
